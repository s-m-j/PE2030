# Контрпример: безопасное расширение на новый район

> **Роль в лекции:** контрпример к [`ai_generalization_pr.md`](ai_generalization_pr.md), используется в блоках 6 и 7 сценария ([../script.md](../script.md)). Показывает ту же задачу, решённую через явное расширение и характеризующий тест, без потери поведения первого района.

## Шаг 1. Характеризующий тест — фиксируем поведение первого района ДО изменения

```python
def test_characterize_district_1_behavior():
    """
    Характеризующий тест: фиксирует текущее (до расширения на Северный
    район) поведение классификации для официальной станции S4. Не
    проверяет "правильность" — проверяет, что поведение не изменится.
    """
    # Реальный случай: 14 июня, умеренное превышение на станции S4.
    complaint = Complaint("C-14-06", "ул. Садовая, 12", datetime(2026, 6, 14, 19, 0))
    measurements = [
        Measurement("S4", "PM2.5", 40.0, "µg/m³", datetime(2026, 6, 14, 19, 0)),
    ]
    result = classify(complaint, measurements, adapters=SOURCE_REGISTRY)
    assert result["status"] == "отклонение"
    assert result["approximate"] is False
```

Этот тест не существовал до расширения на новый район — он написан целенаправленно, потому что задача (расширение источников) создаёт риск именно для этого поведения. Любое изменение, ломающее этот тест, должно быть явно объяснено, а не тихо пропущено.

## Шаг 2. Явное расширение реестра вместо эвристики

```python
NORTHERN_OFFICIAL_STATION = SourceAdapter(
    source_type="official_station",
    unit="µg/m³",
    to_reference_scale=lambda v: v,
    is_approximate=False,
    calibration_note="прямое измерение PM2.5, эталонная шкала, Северный район",
)

NORTHERN_LOW_COST_SENSOR = SourceAdapter(
    source_type="low_cost_sensor",
    unit="index_0_500",
    to_reference_scale=lambda v: v * 0.12,
    is_approximate=True,
    calibration_note="грубое приближение, Северный район, см. ADR лекции 4",
)

SOURCE_REGISTRY = {
    "S4": OFFICIAL_STATION,             # первый район — без изменений
    "D1": LOW_COST_SENSOR,              # первый район — без изменений
    "S-N1": NORTHERN_OFFICIAL_STATION,  # новый источник, явно поименован
    "D-N1": NORTHERN_LOW_COST_SENSOR,   # новый источник, явно поименован
}
```

Реестр остаётся явным. Тип источника не угадывается по значению — он известен заранее, при регистрации.

## Шаг 3. Запуск характеризующего теста после изменения

Тест из шага 1 запускается без изменений и продолжает проходить — потому что логика для `"S4"` не тронута. Расхождение, которое молча возникло в [`ai_generalization_pr.md`](ai_generalization_pr.md), здесь физически не может произойти: `get_adapter("S4")` по-прежнему явно возвращает `OFFICIAL_STATION`, независимо от значения измерения.

---

## Чем это отличается от обобщения через эвристику

| | Обобщение (`infer_adapter`) | Явное расширение реестра |
|---|---|---|
| Добавление нового источника | Не требует правки кода | Требует одну новую запись в реестре |
| Определение типа источника | По диапазону значения — неоднозначно | По идентификатору — однозначно |
| Поведение для `"S4"` при значении 40.0 | Молча меняется (`отклонение` → `обычный уровень`) | Не меняется |
| Что показывает тест | Ничего не ловит — новый тест не про старый район | Характеризующий тест ловит любое расхождение |
| Стоимость добавления N-го района | Постоянная (0 строк) | Линейно растёт (по записи на источник) |

Открытый вопрос для обсуждения на лекции: при каком количестве районов линейный рост реестра станет достаточно дорогим, чтобы вернуться к идее обобщения — на этот раз, вероятно, дополнив её характеризующими тестами для всех существующих источников, а не отбрасывая их.
