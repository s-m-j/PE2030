# Предложение AI: обобщённое определение источника данных

> **Роль в лекции:** второй запрос к тому же AI, показывается в блоке 3 сценария ([../script.md](../script.md)) сразу после того, как в блоке 2 команда получила от него честную реконструкцию контекста ([`ai_context_reconstruction.md`](ai_context_reconstruction.md)). Показывается как готовый результат, без указания на скрытую регрессию. Разбор открывается в блоке 3 и продолжается в блоке 4 (почему один и тот же AI получил разную степень доверия) и блоке 6.

## Промпт

```
Нам нужно добавить новый район (Северный) со своими датчиками и станцией.
Сейчас источники данных регистрируются вручную по идентификатору станции.
Обобщи механизм так, чтобы новые источники подключались без ручной
донастройки — определяй тип источника автоматически.
```

## Существующий код (до обобщения, из лекции 4)

```python
SOURCE_REGISTRY = {
    "S4": OFFICIAL_STATION,   # официальная станция, первый район
    "D1": LOW_COST_SENSOR,    # недорогой датчик, первый район
}

def get_adapter(station_id: str) -> SourceAdapter:
    return SOURCE_REGISTRY[station_id]
```

Каждый источник регистрируется явно, с явно указанным типом — так, как описано в [ADR о нормализации данных](../../04_decisions_expensive_to_change/assets/adr_data_normalization.md).

## Ответ AI: обобщённая версия

```python
def infer_adapter(measurement_value: float) -> SourceAdapter:
    """
    Определяет тип источника по диапазону значения — без ручной
    регистрации. Работает для любого нового источника "из коробки".
    """
    if 0 <= measurement_value <= 500:
        return LOW_COST_SENSOR
    return OFFICIAL_STATION


def classify(complaint, measurements) -> dict:
    nearest = find_nearest_measurement(complaint, measurements)
    if nearest is None:
        return {"status": "недостаточно данных"}
    adapter = infer_adapter(nearest.value)
    value = adapter.to_reference_scale(nearest.value)
    return {
        "status": "отклонение" if value > 35.0 else "обычный уровень",
        "approximate": adapter.is_approximate,
    }
```

> **Комментарий AI к изменению:** «Убрал ручной реестр `SOURCE_REGISTRY` — теперь любой новый датчик или станция, включая Северный район, будет работать без дополнительной настройки. Код стал короче и не требует сопровождения реестра при добавлении источников».

Тесты, приложенные к изменению, проверяют новый район и проходят.

---

## Что скрыто за этим изменением (не показывать до блока 2 — материал для разбора)

Обобщение работает для нового района и для типичных значений старого. Проблема — в конкретном пограничном случае, который стоит найти самостоятельно (см. блок 2 сценария), прежде чем читать дальше.

- **Эвристика определяет тип источника по числовому диапазону значения, а не по тому, что именно измерено.** Диапазон `0–500` пересекается: показания официальной станции (µg/m³) в норме тоже попадают в этот диапазон, включая случаи реального превышения.
- **Конкретный регрессионный случай:** станция S4 первого района 14 июня зафиксировала 40 µg/m³ — умеренное, но реальное превышение норматива (порог классификации — 35.0). При старом явном реестре `get_adapter("S4")` возвращает `OFFICIAL_STATION`, коэффициент масштабирования — тождественный, `classify` корректно возвращает `"отклонение"`.
- При новой логике `infer_adapter(40.0)` подставляет `LOW_COST_SENSOR`, потому что `40` находится в диапазоне `0–500` — значение домножается на коэффициент `0.12`, получается `4.8`, что ниже порога `35.0`. Результат — **`"обычный уровень"` вместо `"отклонение"`.** Реальное превышение стало невидимым для системы.
- **Ни один тест, приложенный к изменению, не покрывает этот случай** — все новые тесты написаны для Северного района; ни один не проверяет старые данные первого района на диапазоне, где эвристика неоднозначна.
- **Это не гипотетический риск, а точное повторение исходной проблемы лекции 1** — «жители жалуются, а датчики не показывают превышения». Только на этот раз превышение произошло, было корректно зафиксировано полгода назад, а регрессия молча вернула систему к тому самому симптому, ради устранения которого она изначально создавалась.

Сравните с тем, как та же задача решается без потери этого поведения, в [`safe_extension_example.md`](safe_extension_example.md).
