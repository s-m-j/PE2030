# Обновление для семинара B: приблизительное время жалоб

> **Роль в семинаре:** вводится в блоке 3 [`../seminar_b.md`](../seminar_b.md), после того как группы уже защитили свою спецификацию инкремента.

## Новый факт

> Специалист экологической службы, проверяя первые результаты сопоставления, обнаруживает: примерно треть жалоб в журнале обращений не содержит точного времени — жители часто пишут на следующий день, указывая «вчера вечером» или «около 9 вечера, может, чуть позже». Точное сопоставление с точностью до часа, заложенное в критерий приёмки, для этой трети жалоб невозможно в принципе — не из-за качества датчиков, а из-за формы, в которой подаются жалобы.

## Три пути, ни один не выбран заранее

1. **Изменить критерий приёмки** — сопоставлять по более широкому окну (например, «вечер», 18:00–23:00) вместо точного часа, признав меньшую точность сразу.
2. **Сузить границы инкремента** — работать в первой версии только с той третью (или двумя третями) жалоб, где время указано точно, явно исключив остальные из этой версии.
3. **Получить дополнительные данные** — например, добавить в форму жалобы (лекция 3 связана с формой из лекции 1 и её последующих версий) обязательное или хотя бы структурированное поле времени, отложив анализ неточных жалоб до следующей версии формы.

## Материал для разбора

Ни один из трёх путей не является «правильным по умолчанию» — выбор зависит от того, кто аудитория первого инкремента (см. блок 4 семинара A) и что было решено как решение пользователя для неё. Если аудитория — специалист, которому нужна воспроизводимая точность, сужение границ может быть честнее, чем ослабление критерия. Если аудитория — руководитель центра с тремя числами для горсовета, широкое окно сопоставления может быть вполне достаточным.

Вопрос для обсуждения: меняется ли ответ в зависимости от того, какую из трёх аудиторий блока 4 семинара A ваша группа выбрала как основную?
