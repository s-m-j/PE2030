# Контрпример: тот же backlog с явными границами мандата

> **Роль в лекции:** контрпример к [`agent_backlog_run.md`](agent_backlog_run.md), используется в блоках 4–6 сценария ([../script.md](../script.md)). Показывает ту же работу, разбитую на отдельные задачи с явными исключениями, точками остановки и полным журналом для ревью.

## Задача 1 — только подтверждённая работа

```
Подключи районы 8–12 по образцу уже существующих (см. source_adapters.py
и записи в source_config для районов 1–7). Каждый район — отдельный
коммит с собственным тестом.

НЕ трогай ничего, кроме регистрации источников для этих пяти районов.
В частности: не изменяй файлы вне source_adapters.py и связанных
тестов; не реализуй и не включай issue #23 (кеширование) — она помечена
как "needs discussion", а не как задача; не удаляй никакие файлы.

После каждого района — остановись и покажи diff перед следующим шагом.
```

**Результат:** пять коммитов, каждый — один новый район, каждый показан на подтверждение перед следующим. Задача полностью соответствует явно установленным границам, потому что границы были явно установлены.

## Задача 2 — отдельно, с явным вопросом человеку

```
Прочитай issue #23 (предложение о кешировании find_nearest_with_adapter)
и подготовь анализ: действительно ли кеширование нужно при текущей
нагрузке (12 районов), какой риск создаёт TTL 5 минут для критерия
приёмки из лекции 3, и какие есть альтернативы. НЕ реализуй и не
включай кеширование — подготовь только анализ для решения человеком.
```

**Результат:** документ-анализ, а не код. Решение о том, включать ли кеширование, остаётся открытым и явно передаётся на рассмотрение команде — ровно то разделение, которого не было в исходном мандате [`agent_backlog_run.md`](agent_backlog_run.md).

## Задача 3 — стилистическая чистка, отдельно и с ограниченным охватом

```
Issue #24 просит стилистическую чистку data_io.py и reporting.py.
Выполни только форматирование и переименования, ТОЛЬКО в этих двух
файлах. Не трогай другие файлы, даже если в них похожий стиль. Не
меняй логику — только стиль. Покажи diff целиком перед коммитом.
```

**Результат:** ограниченное по охвату изменение, которое можно полностью просмотреть за несколько минут, а не как часть большого потока коммитов вперемешку с содержательными изменениями.

## Задача 4 (отдельно) — обнаружение неиспользуемых файлов, без права на удаление

```
Найди файлы в репозитории, на которые не ссылается ни один активный
тест или модуль. Составь список с кратким описанием происхождения
каждого файла (по истории git и комментариям). НЕ удаляй ничего —
верни только список для рассмотрения человеком.
```

**Результат:**

```text
tests/fixtures/district_1_historical/ — 3 файла.
Происхождение: добавлены в коммите "add characterization test for
district 1" (лекция 10). Не импортируются напрямую ни одним активным
тестом. Комментарий в соседнем README указывает: "справочные данные
для будущих характеризующих тестов при расширении". Рекомендация:
не удалять без подтверждения человека, знакомого с историей лекции 10.
```

Агент нашёл ровно тот же факт (на файлы не ссылаются активные тесты), но не сделал вывод об их ненужности самостоятельно — вместо этого явно передал контекст (историю происхождения) человеку для решения.

## Сравнение с исходным мандатом

| | `agent_backlog_run.md` | Этот контрпример |
|---|---|---|
| Формулировка задачи | Одна общая цель на весь backlog | Четыре отдельные задачи с явными границами |
| PR#3 (кеширование) | Реализовано и включено самостоятельно | Подготовлен анализ, решение — за человеком |
| PR#4 (стилистика) | Применено по всей кодовой базе | Ограничено двумя явно названными файлами |
| Фикстуры лекции 10 | Удалены как «неиспользуемые» | Найдены, но не удалены — передан список с контекстом |
| Точки остановки | Отсутствуют — один общий отчёт в конце | После каждого шага, требующего решения |
| Проверка происхождения | Требует разбора общего диффа в 1840+ строк | Каждое изменение просматриваемо по отдельности |

Суммарно эта версия требует больше отдельных обращений к агенту и больше времени человека на промежуточные подтверждения — но ни одно решение, требующее человеческого суждения, не было принято агентом самостоятельно.
