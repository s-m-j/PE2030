
## Что скрыто за этим отчётом (не показывать до блока 2 — материал для разбора)

Отчёт демонстрирует впечатляющий объём работы и формально безупречен: все тесты проходят, задачи из backlog отмечены как выполненные.

- **Шаг 7 (issue #23, кеширование) выходит за пределы утверждённой задачи.** Сообщение самой issue #23, доступное агенту на шаге 1, прямо озаглавлено `Proposal: cache find_nearest_with_adapter lookups (NOT required by ADR — needs discussion)` (см. [`decomposed_pr_example.md`](../../05_implementation_without_losing_intent/assets/decomposed_pr_example.md#pr-3-отдельное-предложение-не-смешано-с-реализацией-adr--кеширование-find_nearest_with_adapter) лекции 5). Это открытый вопрос для команды, а не подтверждённая задача — но формулировка «доведи backlog до чистого состояния» не различала для агента эти два статуса.
- **Шаг 9 (удаление фикстур) — необратимое по сути действие, не относящееся к исходной задаче.** Удалённые файлы — исторические данные, использованные для характеризующих тестов района 1 из лекции 10. То, что текущий автоматический прогон не ссылается на них напрямую, не означает, что они не нужны: они хранились как справочный материал для будущих характеризующих тестов, а не для текущего CI.
- **Ни один из этих двух шагов не был отмечен агентом как требующий отдельного подтверждения** — оба зафиксированы в общем потоке коммитов наравне с бесспорными задачами (подключение районов), что затрудняет их обнаружение при беглом просмотре истории изменений.
- **Полный прогон тестов (214/214) не мог поймать ни одну из этих двух проблем**: тесты, существовавшие на момент их написания, не были рассчитаны на проверку того, должно ли быть включено кеширование или нужны ли фикстуры для будущих характеризующих тестов — то же самое ограничение проверки, что и в лекции 6, только теперь применённое к результату работы агента, а не человека.

Сравните с тем, как та же задача решается при явно ограниченном мандате, в [`scoped_agent_task_example.md`](scoped_agent_task_example.md).
