# Контрпример: короткое обновление к существующему ADR

> **Роль в лекции:** контрпример к [`ai_onboarding_summary.md`](ai_onboarding_summary.md), используется в блоке 5 сценария ([../script.md](../script.md)). Показывает, как небольшая, своевременная запись предотвращает расхождение, из которого выросло правдоподобное, но неверное объяснение AI.

## Дополнение к ADR: нормализация данных источников

**Исходный документ:** [`adr_data_normalization.md`](../../04_decisions_expensive_to_change/assets/adr_data_normalization.md) (лекция 4).

**Дата дополнения:** момент проведения миграции реестра источников (лекция 11).

---

### Что изменилось технически

Начиная с миграции на конфигурацию в базе данных (`source_config`), значения `coefficient`, `is_approximate` и `calibration_note` для каждого источника хранятся не в константах кода (`OFFICIAL_STATION`, `LOW_COST_SENSOR`), а как записи таблицы конфигурации, редактируемые через административный интерфейс.

### Что осталось без изменений (и почему это важно явно повторить)

- **Обоснование и условие пересмотра коэффициента `0.12` из исходного ADR остаются в силе.** Это по-прежнему грубое, необоснованное лабораторно приближение, предназначенное только для приоритизации, а не для точных выводов.
- **Условие пересмотра не изменилось**: коэффициент должен быть пересмотрен при появлении второго недорогого источника с иной шкалой, при предъявлении результата внешней аудитории (это условие уже наступало в лекции 9) или при появлении возможности лабораторной калибровки.
- **Перенос значения в конфигурацию не означает, что оно стало более обоснованным.** Административный интерфейс упрощает *смену* источника данных, а не *обоснованность* конкретного значения коэффициента.

### Явная рекомендация для новых источников

При регистрации нового источника через административный интерфейс **не копировать** значение коэффициента соседнего района автоматически. Значение по умолчанию можно использовать как отправную точку, но лицо, регистрирующее источник, должно явно подтвердить (записью в поле `calibration_note`), что оно осознаёт условность этого значения — форма в административном интерфейсе теперь требует заполнения этого поля, а не оставляет его опциональным.

---

## Почему это дополнение эффективнее полного переписывания

- Оно **не отменяет** исходный документ — сохраняется прослеживаемость от первоначального решения лекции 4 через все последующие изменения.
- Оно **короткое и целевое** — написание заняло несколько минут в момент миграции, а не требовало отдельной задачи «актуализировать документацию», которая обычно откладывается на неопределённый срок.
- Оно **явно называет то, что могло быть неверно домыслено** — условие пересмотра и предупреждение против копирования значения указаны прямо, а не оставлены для реконструкции по коду.

Если бы это дополнение существовало на момент, когда новый инженер задал свой вопрос AI ([`ai_onboarding_summary.md`](ai_onboarding_summary.md)), у модели был бы доступ к актуальному, а не только историческому контексту — и итоговый обзор, вероятно, не содержал бы ложного утверждения о калибровке по историческим данным.
