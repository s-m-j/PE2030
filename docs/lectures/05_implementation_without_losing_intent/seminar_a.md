## Ход семинара

### Блок 2. Индивидуальная классификация содержимого большого PR (12 мин)

Каждый студент самостоятельно читает [`assets/ai_generated_giant_pr.md`](assets/ai_generated_giant_pr.md) и относит каждую часть diff'а к одной из трёх категорий: реализует ADR лекции 4 / посторонний рефакторинг / рискованное добавление, требующее отдельного решения (кеширование).

### Блок 3. Малые группы: что принять, что отклонить, что вынести отдельно (15 мин)

Сравнить классификации. Согласовать: какую часть PR группа приняла бы сразу, какую отклонила бы полностью, какую попросила бы вынести в отдельное изменение.

**Опорный вопрос:** ни одна часть этого PR не является технически ошибочной сама по себе — тогда на каком основании вы отклоняете или откладываете часть из них?

### Блок 4. Переформулировать первый запрос (20 мин)

Используя бланк [`scoped_delegation_prompt.md`](../../course/seminar_templates/scoped_delegation_prompt.md), группа переписывает исходный запрос («реализуй по ADR весь пилотный инкремент целиком») в 2–4 отдельных запроса, каждый с явным шагом, интерфейсом, обязательными тестами и границей «что не трогать».

**Опорный вопрос:** кеширование и переформатирование, добавленные без спроса в исходном PR, — куда они должны деться в переформулированной версии: исчезнуть совсем, или превратиться в отдельный, явно обсуждаемый запрос?

### Блок 5. Сравнение со стандартной декомпозицией (13 мин)

Показать [`assets/decomposed_pr_example.md`](assets/decomposed_pr_example.md) — как то же решение декомпозировали постфактум для лекции. Сравнить с собственной версией группы из блока 4: совпадает ли число шагов, совпадает ли то, что вынесено в «отдельные предложения» (PR#3–4)?

**Опорный тезис:** узко очерченное делегирование [`ai_scoped_adapter_success.md`](assets/ai_scoped_adapter_success.md) было спроектировано узким с самого начала, а не разделено постфактум, как декомпозированный пример, — оба подхода работают, но первый дешевле по суммарному времени команды.

### Блок 6. Индивидуальная фиксация (10 мин)

Каждый студент индивидуально записывает: один запрос из своей переформулировки блока 4, которым он доволен больше всего, и объясняет, какой из четырёх элементов шаблона в нём труднее всего было сформулировать точно.

## Индивидуальная фиксация (сдаётся)

Классификация блока 2 (уточнённая после блока 3) + переформулированные запросы блока 4 + пункт блока 6. Основа для самостоятельной работы (`model.md`: декомпозиция реализации ADR на шаги с явной границей, минимум один шаг делегирован AI с явно сформулированной границей).

## Наблюдаемые свидетельства

- Студент способен разделить большое, технически корректное изменение на «реализует решение» / «постороннее улучшение» / «рискованное добавление, требующее отдельного решения».
- Студент способен сформулировать запрос к AI, включающий все четыре обязательных элемента границы делегирования.
- Студент способен объяснить, почему заранее спроектированная узкая задача обычно дешевле, чем декомпозиция постфактум того же результата.

## Вопросы для доработки

- Проверить, не начинают ли студенты в блоке 4 формулировать границу «постфактум», уже зная результат обоих PR, вместо того чтобы тренироваться формулировать её заранее (см. открытый вопрос `model.md`) — возможно, стоит дать смежную, но не идентичную задачу для самостоятельной переформулировки.
- Решить, показывать ли `decomposed_pr_example.md` целиком в блоке 5 или только таблицу сравнения в его конце.
