# Материалы для лекции 12

## Файлы

- [`ai_incident_patch.md`](ai_incident_patch.md) — предложение AI: срочное исправление во время реального инцидента (неограниченные повторные попытки без задержки и идемпотентности), которое устраняет видимый симптом и создаёт менее заметный, но более серьёзный риск. Используется в **блоках 1–2** сценария ([../script.md](../script.md)).
- [`graceful_degradation_example.md`](graceful_degradation_example.md) — контрпример: изоляция отказа по районам, ограниченные идемпотентные повторные попытки с backoff, явная деградация, мониторинг зависания через SLO свежести данных. Используется в **блоке 5**.
- [`incident_logs.md`](incident_logs.md) — материал для упражнения по восстановлению хронологии инцидента из неполных, частично противоречивых источников (логи, чат команды, письмо техподдержки). Используется в **блоке 7**. Не содержит единственно правильного разбора — цель упражнения в явном разделении факта и интерпретации, а не в поиске «правильной» версии событий.

## Как использовать на занятии

`ai_incident_patch.md` показывается в блоке 1 как уже развёрнутое, принятое под давлением решение — важно передать ощущение реального времени инцидента, а не разбора задним числом. `incident_logs.md` раздаётся по группам без заранее подготовленного «эталонного» постмортема.

## Статус

Черновик, учебный пример. Числа, время и код подобраны ради иллюстрации риска непродуманной реакции на инцидент и техники восстановления хронологии, а не как реальные инцидент-данные `pe2030-air-quality-pilot`.
