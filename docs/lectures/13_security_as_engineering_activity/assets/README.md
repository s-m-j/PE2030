# Материалы для лекции 13

## Файлы

- [`ai_quick_auth_patch.md`](ai_quick_auth_patch.md) — предложение AI: срочная защита административного интерфейса паролем на веб-форме, оставляющая реальный API-эндпоинт открытым, пароль общим и захардкоженным, без журналирования. Используется в **блоках 1–2** сценария ([../script.md](../script.md)), разбор завершается в **блоке 5**.
- [`proper_access_control_example.md`](proper_access_control_example.md) — двухчастный контрпример. Часть 1: проверка прав на уровне API, именные учётные записи, ограничение диапазона допустимых значений, журналирование действий — используется в **блоке 6**. Часть 2: спустя время аудит по журналу из части 1 обнаруживает, что легитимный, авторизованный специалист вышел за пределы своей области ответственности, — используется в **блоке 7**.

## Как использовать на занятии

`ai_quick_auth_patch.md` показывается как уже развёрнутое, принятое под давлением решение — важно передать ощущение, что «проблема как будто решена», прежде чем аудитория найдёт оставшиеся дыры. Части `proper_access_control_example.md` показываются с разрывом во времени внутри сценария, не подряд: часть 1 — как решение, закрывающее находку блока 2; часть 2 — как отдельный разворот в блоке 7, после того как аудитория уже приняла часть 1 за полное решение. Ситуация прямо продолжает административный интерфейс из [лекции 11](../../11_refactor_migrate_or_leave/) — стоит свериться с ним при подготовке.

## Статус

Черновик, учебный пример. Код и находки написаны ради иллюстрации разницы между security through obscurity и настоящим контролем доступа, а не как рекомендация для реальной архитектуры `pe2030-air-quality-pilot`.
